`0fcdce5f4fdec8d442d7df760cb541f1ca6e446d`. GA preparation targets the latest
full stable Windows branch, 152.0.7977.83, verified upstream commit
`79460ebecaa5625e57a5fb679a735659e73dc687`. The Chrome team's

reports 12 security fixes, including an actively exploited V8 vulnerability.
Chromium 153 is currently an early stable rollout; 152 is the full stable
baseline selected for this candidate.

Keep the existing checkout and all its local edits intact. Capture the current
TAHAI source in a local Git snapshot, port the combined TAHAI changes onto the
verified upstream tag in a separate checkout, and retain source/dependency
provenance. Update the actual engine and its pinned dependencies; changing
`chrome/VERSION` alone is not an engine update.

## Port progress

The original checkout and index were captured without modification in snapshot
`d72fb7d21d2cd517a31acd9d8c68b86e3037bda9`. The separate Windows GA source at
`C:\src\TAHAI-GA\src` now has upstream 152 as its parent and the cumulative port
in `d7560a7220`. Its unmanaged gclient root preserves the TAHAI branch while
syncing the pinned upstream dependencies. The original source remains at
`C:\src\TAHAI-Chromium\src`.

The port retains upstream dependency modularization, moves TAHAI commands to
the non-overlapping 34500–34528 range, and appends the 16 TAHAI policy IDs after
upstream's 1476 (local policy names and preference keys remain stable). The
upstream shared split-tab view now carries TAHAI's 2–4 pane layout/drop support.
The creator kit targets Chromium 152 and retains strict compatibility checks
for older user packages. Runtime acceptance is still pending.

To avoid duplicating the large build output, the new checkout's
`out\tahai_release_x64` is a directory junction to the existing physical output.
GN must regenerate from the new checkout and the release evidence must identify
the new source. Old binaries and old logs are not current verification evidence.

Additional port hardening:

- Required browser tests now include all 16 TAHAI policy mappings and a
  four-pane move/close/exit regression. The pane code preserves live content
  views instead of treating every tab change as a two-pane swap.
- Packaging checks the executable, DLL and runtime manifest engine versions
  against `chrome/VERSION`; its receipt records version/DEPS/build-argument
  hashes. The old 150 executable was rejected by the new version check.
- The verification runner records its process identity and archives the four
  previous outputs before building, so each new release interval requires real
  relinking. It does not adjust output timestamps.
- The five creator tests and 24 synthetic packaging-guard checks pass. The
  synthetic browser fixture now has 107 attempts; none is native runtime proof.

## Acceptance

- Fresh non-component x64 binaries and actual build exit/log evidence.
- All native TAHAI tests, all discovered TAHAI browser tests, and the relevant
  Chromium policy-to-preference mappings, with no retries or skipped failures.
- Real isolated-profile native UI checks for Guard network/cosmetic filtering,
  recovery, policy/private boundaries and the complete skin lifecycle/Studio.
- Full credits and exact shipped filter/creator resources verified in the PAK.
- MSIX manifest, payload hashes, source notices and fresh evidence verified.
- Signed-package install/upgrade/uninstall and accessibility/DPI checks in a
  controlled test environment before declaring general availability.

The unsigned Store submission artifact and a signed, installed GA release are
distinct results. Do not claim Store certification, publication, or successful
installation without the corresponding evidence.
