# Troubleshooting states

**Screenshot target:** `docs/kb/screenshots/18-error-empty-blocked-state.png`

## Screenshot capture checklist

- **File to add later:** `18-error-empty-blocked-state.png`
- **Capture:** Capture one useful troubleshooting state such as disabled integration, offline state, blocked unsafe URL, redaction warning, or empty state.
- **Must show:** The warning/empty/blocked message; Suggested user action; No stack trace unless it is an intentional dev-only screenshot
- **Avoid:** Raw errors containing paths or secrets; Sensitive URLs or tenant IDs

## What this feature does

Disabled, empty, blocked, and warning states should explain what happened and what the user can do next.

## How to use it

Use these screenshots to document offline state, session-expired state, blocked unsafe URL/protocol, redaction warning, or unavailable integration states.

## Safety notes

- Keep secrets, tokens, cookies, runtime browser profiles, generated installers, and local data out of source.
- IT Docs and PSA references remain browser-side display/context unless a server-authorized workflow exists.
- Treat Mission files and exported evidence as untrusted until validated and redacted.
