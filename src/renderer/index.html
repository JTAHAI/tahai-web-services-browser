TAHAI Web Services Browser

Runtime settings

Settings are stored in your local app profile. Reset restores https://tahaiportal.com as the default home page.

Permission prompts remain locked down: camera, microphone, clipboard-read, geolocation, and notifications are denied unless the site is HTTPS or localhost and the matching setting is enabled.

Popup windows are handled by the main process and, when enabled, open as sanitized TAHAI tabs instead of unmanaged external popup windows. Unsafe popup URLs remain blocked.

Download status uses sanitized file names only. The browser does not expose local file paths to web pages, and executable or installer downloads are flagged before opening or sharing. Mission, profile, and evidence saves show safe labels instead of local paths.

Mission drag-and-drop accepts only internal TAHAI mission payloads. External files, URLs, HTML, and text drops are blocked before they reach Mission controls.

Active-page capture is redacted, URL-normalized, size-capped, and source-sanitized before preview, pinning, copy, save, or diagnostics use.

Runtime settings are size-capped and sanitized before saving. Home pages must be HTTPS or localhost HTTP, and the Settings screen never exposes local download paths.

Ops diagnostics use cookie-free requests through a cookie-free request path and block localhost, private/link-local ranges, metadata endpoints, single-label internal hosts, unsafe DNS results, and redirect targets. Diagnostic output must never include Cookie or Authorization output.

Remote page titles, status text, Mission timeline entries, and Mission metadata URLs are sanitized before display or local Mission use, preventing hostile metadata from carrying control characters, bidi spoofing, embedded credentials, or tokenized query strings into evidence.

TAHAI Browser Profiles

Profiles

Profiles isolate cookies, sessions, storage, cache, permissions, and service login state.

Profiles use separate Electron session partitions. Account labels are local-only; no Chrome Sync, browser cloud sync, PSA tokens, provider API keys, cookies, or OAuth refresh tokens are stored in TAHAI mission/profile metadata.

TAHAI DevOps Evidence

Documentation-ready capture

Captures the active tab URL, title, visible page structure, basic timing, and a runbook-ready incident/change template. It intentionally avoids cookies, localStorage values, passwords, tokens, and form contents. Copy and save actions run through a second main-process redaction boundary before clipboard or disk handoff. Local filesystem paths are hidden after saves, and active-page capture output from remote webviews is sanitized before preview, pinning, copy, or save.

TAHAI IT / DevOps Diagnostics

URL operations check

Runs a safe HEAD request against the active URL, summarizes HTTP status and operational headers, and outputs a documentation-ready checklist for IT engineering, DevOps, QA, and support. It excludes cookies, authorization headers, request bodies, localStorage values, and form contents.

TAHAI DevOps Engineering

Deploy Readiness

Creates a deployment-ready Markdown report for release/change tickets, rollback planning, smoke checks, and post-deploy verification. It combines safe HTTP/header diagnostics, active-page context, load timing, and console error/warning counts. It excludes cookies, authorization headers, request bodies, response bodies, storage values, credentials, tokens, and form contents.

TAHAI IT Engineering Documentation

IT Service Card

Creates a documentation-ready service profile for the active URL with public DNS, safe HTTP headers, page context, ownership placeholders, access notes, monitoring/recovery fields, and TAHAI IT Docs handoff checks. It excludes cookies, authorization headers, request bodies, response bodies, storage values, credentials, tokens, and form contents.

Endpoint Snapshot

Creates a safe browser/client environment profile for helpdesk, endpoint troubleshooting, implementation notes, and TAHAI IT Docs handoff. It captures platform, language/timezone, screen/viewport, online state, permission states, storage availability booleans, and active URL context only. It does not read cookies, clipboard contents, storage values, passwords, tokens, local files, IP addresses, or form contents.

TAHAI IT Engineering Support

Support Triage

Creates a helpdesk-ready support/escalation packet from the active tab with safe page context, endpoint/browser signals, HTTP reachability, console error counts, impact fields, reproduction prompts, and escalation checklist. It excludes cookies, storage values, clipboard contents, passwords, tokens, local files, IP addresses, request bodies, response bodies, and form contents.

TAHAI Evidence / Change Control

Evidence Pack v3 Composer

Builds a local Markdown bundle from pinned Evidence Timeline items, saved workspace snapshots, active profile context, and IT Docs / PSA handoff fields. Redaction safety sanitizes URLs, titles, notes, pinned evidence bodies, and copy/save output before handoff, with a main-process redaction boundary before clipboard or disk output. Save status returns safe labels instead of local paths. It only includes evidence that was explicitly generated or pinned by the user. It does not collect cookies, storage values, credentials, tokens, request bodies, response bodies, clipboard contents, local files, or form values.

TAHAI Operational Handoff

IT Docs / PSA Handoff Center

Creates a focused operational handoff for TAHAI IT Docs today and TAHAI PSA ticket/change workflows when IT Docs authorizes a server-side PSA connector. It sanitizes URLs, titles, notes, pinned evidence bodies, and copy/save output before handoff. It uses active profile context, current tabs, saved workspaces, and explicitly pinned evidence only. The same redaction gate protects privileged copy/save handoff paths, and save status hides local filesystem paths. Privileged shell actions are allowlisted to packaged TAHAI shell pages only; arbitrary local files are blocked from Mission/browser APIs.

Enterprise Support Bundle

Creates a redacted support bundle with version truth, policy truth, install/runtime truth, profile and mission counts, and signing/provenance/SBOM status. No cookies, tokens, raw browser profiles, local paths, or raw mission files.

TAHAI Ops Guard

Redaction Review

Reviews the latest bundle, handoff, or generated tool output before it leaves the browser. It uses shared redaction rules for URL query secrets, credential terms, private keys, provider tokens, auth/cookie headers, and share-risk markers, then creates a redacted copy for external tickets, emails, or vendor handoffs. The same redaction gate protects privileged copy/save paths, and save status hides local filesystem paths.

Creates a documentation-ready frontend route/API surface map from the active tab. It samples same-origin routes, external origins, forms by method/action, resource origins, framework hints, and API-like resource paths. It strips/redacts sensitive URL parts before preview/export and excludes cookies, storage values, credentials, tokens, request bodies, response bodies, form values, clipboard contents, and local files.

Developer Audit

Creates a documentation-ready developer audit from the active tab: console warnings/errors, resource timing, load metrics, page structure, and lightweight quality checks. It strips and redacts sensitive URL parts and sanitizes remote webview capture output before preview or export. It excludes cookies, storage values, credentials, tokens, request bodies, response bodies, and form contents.
